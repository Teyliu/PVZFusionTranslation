## Stage 1 — Batch deobfuscate (PowerShell loop, per DLL)

```
foreach ($dll in plugins-orig/*.dll) {
  UnConfuserEx.exe $dll work/stage1/<name>-deob.dll
  ProxyFixerV2.exe work/stage1/<name>-deob.dll work/stage2/<name>-clean.dll   # hoặc GUI batch
  ghi manifest: exit code + sha256
}
```

Fail policy: DLL nào rớt → cách ly `work/failed/`, thử chain phụ (ConstantsDecryptor → SwitchKiller → ConfuserExFixer → de4dot-cex), vẫn rớt → để lại manual (Recaf/IDA spot-check).

## Stage 2 — Integrity gate (method còn nguyên vẹn)

Per DLL đã clean, so với bản obf gốc:

- `ilspycmd -l type work/stage2/<name>-clean.dll` vs gốc: đếm type/method, diff tên. Kỳ vọng: số method giữ nguyên hoặc tăng nhẹ (proxy unwrap), không mất.
- Recaf search `Confuser|proxy|Activator.` còn sót → fail thì chạy lại fixer.
- Chỉ DLL pass gate mới sang Stage 3. Ghi số liệu vào manifest (evidence).

## Stage 3 — ilspycmd project + slim theo ref

1. `ilspycmd -p -o work/proj/<Name> work/stage2/<Name>-clean.dll`
2. Slim: gom về layout `Plugin.cs | Core/ | Runtime/ | Patches/`; csproj thay bằng Template.csproj (sửa AssemblyName/BepInPlugin GUID + EmbeddedResource bundle name); xóa junk (renamer remnants, NOP types, `<>c` rác không dùng).
3. Bundle nhúng: extract tên resource, đặt tên chuẩn `<mod>` (như `anime` của AnimeTest).
4. `dotnet build -c Release` với GamePath live. Lỗi thiếu interop type (game 3.9 đổi API, vd `GetDamage long`) → vá theo pattern hiện tại của repo translator (đã fix 3 file 3.9 trước đó).
